# 验证范围

当前版本验证日期：2026-11-17（Asia/Shanghai）。不包含用户正在进行的手动测试结论。

## v0.2.1

- Windows、Android 与 all 三个安装包仅含 spine 文件夹；安装到模拟已有项目后，原有 script.rpy、screens.rpy、options.rpy、gui.rpy、其他 Python 库、工具和自有模型字节保持原样。all 包与两个平台包的文件并集完全一致。
- 使用 Ren’Py 8.5.3.26051504 的独立项目，从实际生成的 all.zip 安装；Python 模块与资源分别以散文件及 RPA 归档两种形式加载，五个版本均通过 Render/Mesh2 构建及 pickle 恢复。原有 Python 依赖仍可导入，示例未在初始化时创建角色。这里使用纹理占位，不是 GPU 画面验证。
- 从分散布局升级时，旧入口或旧 Python 包会触发带清理说明的错误，避免混用。复现命令为 SDK 自带 Python 执行 `tests/renpy-install.py --renpy-sdk <SDK目录>`，需先生成安装包并获取测试素材。
- 目录迁移后，自制 3.8、58 个官方导出、20 个库与 541 个源码哈希审计、四种 APK/AAB 注入检查再次通过。没有修改官方运行时文件或重新设计序列化协议。

## v0.2.0

- 五个后端共 541 个官方源码文件与已提交的固定 SHA-256 清单完全一致；4.x 原文件直接编译，3.8 保留原有生成阶段附件修正。
- 本地 Windows x64 与 Android 三种 ABI 共 20 个原生库通过 CPU 架构和动态依赖检查；15 个 Android ELF 均满足 16 KB 段对齐，4.3 不依赖额外的 C++ 共享库。
- 自制 3.8 几何测试通过，连续 120 帧存档恢复最大顶点误差为 0。
- 58 个官方 JSON/SKEL 文件通过原生多版本检查：5568 帧动画、2610 帧恢复后逐帧比较，包含顶点、UV/双色属性、索引、骨骼矩阵及后续事件。
- 序列贴图使用 4.1/4.2 dragon、4.3 diamond；物理约束使用 4.2 celestial-circus 的 30 个约束、4.3 sack 的 20 个约束。官方示例按 `fixtures-lock-*.json` 下载，不进入仓库或 Release ZIP。
- 四种模拟 APK/AAB 布局的注入检查通过，覆盖五个版本、三种 ABI、单一 ABI 包、原始资源保留及旧签名移除。它们不是已签名或安装到设备的 APK。
- 接入前的真实 Ren’Py 8.5.3 项目通过五个版本的 Render/Mesh2 构建、显示对象序列化、临时输入释放；原有 3.8 存读档、回滚、眨眼、触摸和语音回归通过。此处的自动 Render 检查使用纹理占位，不是 GPU 截图验收。
- CI 在干净 runner 上重建并运行仓库内原生和打包测试；运行结果以 GitHub Actions 对应提交记录为准，流程见 CI.md。

## 提取前的集成回归

以下记录来自适配器提取前的本地项目，相关第三方素材和专项测试没有公开打包。它们不能被当成本仓库原样可运行的测试命令：

- 常规动画、多轨、动画队列、骨骼覆盖、暂停、速度、存读档和回滚。
- 四个随动画骨骼移动的触摸区域；仿射坐标往返最大误差 `2.433608869978343e-13`；按下、拖动、松开、结束动画回归待机。

- 六段音频的事件时序；APK / AAB 注入逻辑；三个 Android ABI 的 ELF 架构和 16 KB 段对齐。
